# 문장 고유키·영구 캐시·파일 이동 · 0.2.0

## 조사 결과: 게임 데이터 ID와 문장 ID는 다릅니다

공개 클라이언트 1.1.122의 코드를 읽기 전용으로 확인했습니다. 로그인 상태·계정 토큰·세이브 데이터는 읽지 않았고 가져온 코드를 실행하지 않았습니다.

- 공개 엔진 `cocos2d-js-min.js`에서 Component/Node의 UUID는 `Comp`/`Node` 객체 인스턴스를 위해 생성됩니다. 문장 고유값이 아니고 같은 표시 객체에서 문구가 바뀔 수 있습니다. Label의 `string` setter에는 문자열만 전달됩니다.
- 공개 게임 번들 `assets/main/index.js`에서 `SkillModel.getSkillId()`, `CharacterMainModel.getCharacterId()`, `AbilityTextFormatModel.getFormatId()` 같은 의미 있는 데이터 ID는 확인됐습니다.
- 예: 스킬 이름은 `skillId`에 연결되지만, 설명은 `skillId + level`과 치환값으로 생성됩니다. 같은 ID라도 업데이트로 문구가 바뀔 수 있습니다. ID 하나만 캐시 키로 쓰면 오래되거나 잘못된 수치의 번역을 재사용할 위험이 있습니다.
- 스토리에는 `StoryMainModel.storyId`/리소스 경로가 있고 커맨드 위치를 추적합니다. 확인한 `CommandMessage → MessageView → AdvText` 표시 경로에서는 모든 대사에 공통으로 적용되는 안정적인 개별 textId를 찾지 못했습니다. 전체 게임에 어떤 다른 키도 없다는 뜻은 아닙니다.
- `AdvText`는 완성 문장의 앞부분을 substring으로 조금씩 보여줍니다. 이를 문장마다 다른 UUID로 캐시하거나 접두사마다 AI에 보내면 비효율적입니다.
- 현재 범용 setter만으로는 모든 의미 ID를 안정적으로 복구할 수 없습니다. 의미 ID를 추가하려면 스킬/캐릭터/스토리별 모델 인지 어댑터가 별도로 필요합니다. 이번 버전은 그러한 의미 ID 어댑터를 설치하지 않습니다.

검토한 공개 경로:

- https://gg-client-r.crave-saga.net/client/1.1.122/src/settings.js
- https://gg-client-r.crave-saga.net/client/1.1.122/main.js

## 실제로 사용하는 고유키

정규화된 배열의 JSON을 SHA-256으로 해시합니다.

```text
["crave-cache-v2", 대상 언어, 정확한 일본어/영문 원문, 짧은 Cocos 표시 문맥]
→ v2:<64자리 SHA-256>
```

- 페이지·게임을 새로 열어도 입력이 같으면 같은 키입니다. Node/Label UUID, 메모리 주소, 임시 요청 ID를 영구 키로 쓰지 않습니다.
- 원문·숫자·공백·태그·언어·문맥 중 하나가 바뀌면 다른 키입니다. 같은 ID의 게임 데이터가 수정되더라도 원문이 다르면 오래된 번역을 쓰지 않습니다.
- 문맥은 가까운 Cocos 컴포넌트의 클래스명 조합입니다. 같은 단어라도 의미가 다른 화면에서는 별도 캐시가 될 수 있습니다. 게임 업데이트로 클래스명이 바뀌면 안전한 재사용 대신 새 항목으로 처리될 수 있습니다.
- provider, 모델, endpoint, API 키는 키에 넣지 않습니다. 모델을 바꿔도 같은 문장은 저장된 번역을 우선합니다. 새 모델로 재번역하려면 캐시를 비우거나 파일 전체 교체를 사용하세요.
- 자체 고유키이지 게임이 원래 제공한 문자열 ID라고 주장하지 않습니다. 암호학적 해시의 충돌 가능성이 이론적으로 0인 것은 아니지만 SHA-256을 사용합니다.

## 조회 순서

1. **MAIN 메모리:** 현재 페이지에서 이미 표시한 번역은 setter 단계에서 동기적으로 재사용합니다.
2. **ISOLATED 메모리:** 새로고침 때 최근 2,000개/2MiB 이내 캐시를 로컬 DB에서 준비합니다. 이 목록 전체를 게임 MAIN 환경에 보내지 않습니다. 현재 원문에 맞는 결과만 답합니다.
3. **IndexedDB:** 메모리에 없으면 별도 빠른 로컬 조회 배치로 확인합니다. 유료 AI 요청의 약 5초 배치 간격이나 이전 AI 응답을 기다리는 대기열에 넣지 않습니다.
4. **AI:** 로컬 저장에도 없는 안정된 문구만 AI 대기열에 넣습니다. 새 결과를 검증하고 원문과 함께 영구 저장합니다.

새 문구는 약 280ms 동안 바뀌지 않았을 때 미캐시 요청 대상으로 확정합니다. 연속적인 스토리 타이핑 접두사 요청을 줄이는 범용 처리이며, 완성 문장 자체를 상위 스토리 모델에서 직접 가져오는 전용 어댑터는 아닙니다. 타이핑 중 길게 멈추는 등 특수한 경우에는 부분 문구가 남을 수 있습니다. 이미지/OCR는 여전히 제외입니다.

같은 페이지의 메모리 적중은 즉시, 새 페이지는 로컬 캐시 준비/조회 후 적용합니다. 완전히 지연 0이거나 모든 실게임 문구에서 같은 속도라는 의미는 아닙니다. 자동 검사에서 서비스 워커를 새로 만든 뒤에도 가져온 캐시가 재사용되고, 캐시 적중 시 HTTP/AI 호출 수가 늘지 않는 것을 확인했습니다.

## 저장과 수명

- 위치: 확장 전용 IndexedDB `crave-ai-cache` / `translations`.
- 저장 필드: `id`, `source`, `context`, `target`, `text`, `createdAt`, `updatedAt`. DB에는 오래된 기록 정리용 `time` 인덱스도 있습니다.
- 브라우저 새로고침/재시작 후에도 같은 확장 ID의 프로필에서는 유지됩니다. 확장 삭제, 프로필 초기화, 확장 ID가 달라지는 폴더 이동/설치 환경에서는 다를 수 있으므로 파일 백업을 권장합니다.
- 최대 20,000개, 내부 직렬화 기준 16MiB. 새 번역 저장 후 초과하면 오래된 항목을 정리합니다. 무한 보관 기능은 아닙니다.
- 캐시에는 스토리 원문/사용자 이름 등이 포함될 수 있습니다. 암호화 금고가 아니며 PC 프로필 접근 권한이 있는 사람으로부터 보호를 보장하지 않습니다.

## 파일 저장 / 불러오기

툴바 확장 아이콘 팝업 → **캐시** 탭 → **번역 캐시 파일**:

- **캐시 JSON 내보내기:** `crave-ai-cache-<시간>.json` 파일을 브라우저 다운로드로 저장합니다.
- **파일 선택 → 가져오기:** `format: crave-ai-translation-cache`, 파일 스키마 `version: 1`을 읽습니다. 앱 버전 0.2.0과 파일 스키마 버전 1은 서로 다른 개념입니다.
- **병합 (기본):** 기존 ID가 있으면 기존 번역을 유지하고 파일의 충돌 항목은 건너뜁니다.
- **전체 교체:** 확인 후 기존 캐시를 통째로 파일 내용으로 바꿉니다. 모든 항목 검증이 끝난 후 하나의 IndexedDB 쓰기 트랜잭션으로 적용합니다. 잘못된 파일을 고르더라도 먼저 지우지 않습니다.
- 파일 제한 32MiB / 20,000개입니다. 실제 불러올 전체 데이터는 DB 내부 한도 16MiB에도 맞아야 합니다. 병합 결과가 한도를 넘으면 조용히 항목을 버리지 않고 오류로 중단합니다.
- 파일 전체 메타데이터·필수 필드·ID·중복·수치·태그·변수·줄바꿈을 검증합니다. ID는 원문/언어/문맥으로 다시 계산합니다. 의미상 오역까지 자동 검증하는 것은 아닙니다.
- 내보내는 JSON에는 원문, 번역, 고유키, 문맥, 언어, 시각과 파일/앱 버전만 있습니다. API 키·브리지 토큰·서버 주소나 로그인 쿠키는 포함하지 않습니다.
- **파일을 공개 번역 배포물로 무단 공유하지 마세요.** 게임 텍스트 저작권과 개인정보가 포함될 수 있습니다.

## API 없이 가져온 파일 사용

설정에서 **캐시 전용 모드 (AI 요청 안 함)** 및 **자동 번역 켜기**를 선택하고 저장합니다. API 키와 전송 동의는 필요하지 않습니다. 가져온 파일의 대상 언어와 현재 설정 언어가 같아야 합니다. 없는 문구는 원문으로 남습니다. 실제 AI 연결 테스트는 이 모드를 끈 뒤에만 가능합니다.

캐시 전용 모드를 켜기 전에 이미 전송한 API 요청의 사용량/비용은 취소되지 않습니다. 모델 목록 조회 등 사용자가 따로 누르는 관리 작업은 일반 연결 기능이므로 네트워크 없는 사용을 원하면 실행하지 마세요.

## 0.1.0 캐시 호환

0.1.0은 provider/endpoint/모델/언어/원문/문맥의 해시와 번역만 저장해 원문을 복원할 수 없습니다. **0.1.0 때와 같은 provider·모델·endpoint 설정에서** 해당 원문이 다시 나타나면 옛 해시를 조회하고, 내용을 검증한 뒤 새 형식으로 승격합니다. 새 canonical 항목이 이미 있으면 오래된 항목으로 덮어쓰지 않습니다.

원문을 알 수 없는 옛 항목은 파일 내보내기에서 제외하고 제외 개수를 표시합니다. 새 버전을 설치했다고 모든 옛 항목을 즉시 새 키로 변환할 수 있는 것은 아닙니다. API 설정을 먼저 바꾸면 옛 키를 찾지 못할 수 있습니다. 이 한계는 0.1.0에 원문/설정 메타데이터를 저장하지 않았기 때문입니다.
